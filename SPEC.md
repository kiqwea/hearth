# ТЗ: десктопное приложение для локальных серверов Minecraft («свой Aternos на ПК»)

## Суть
Приложение для Windows 10/11, которое в пару кликов создаёт и запускает сервер Minecraft **на компьютере пользователя**, чтобы играть с друзьями. Как Aternos, только локально, быстрее и удобнее. Сервер и мир сохраняются между запусками.

Целевой пользователь: геймер без опыта администрирования. Всё, что можно автоматизировать (Java, порты, EULA, конфиги), автоматизируем. Ручная правка файлов не нужна, но опытному пользователю доступна (кнопка «Открыть папку сервера»).

## Стек
- **Tauri v2**: бэкенд на Rust, фронтенд на TypeScript (фреймворк выберем вместе: Svelte или React).
- Сборка на Windows, установщик NSIS.
- Интерфейс: современный, тёмная тема по умолчанию, в духе Modrinth App / Prism Launcher. Детали дизайна обсудим отдельно.
- Язык интерфейса: русский, с заделом под i18n (английский позже).

## Функции

### 1. Создание сервера (мастер)
1. Выбор издания: **Java** или **Bedrock**.
2. Для Java: выбор ядра: Vanilla, Paper, Purpur, Fabric, NeoForge, Forge (Forge/NeoForge можно отложить на этап 3).
3. Выбор версии игры (по умолчанию последняя стабильная, переключатель «показывать снапшоты»).
4. Название, иконка, RAM (ползунок с рекомендацией по объёму ОЗУ ПК), режим игры, сложность, слоты, сид.
5. Опции: «Пиратские клиенты» (только Java), пресет оптимизации, Geyser (пускать Bedrock-игроков на Java-сервер).
6. Показать и принять EULA Mojang (обязательно, с ссылкой). Затем скачивание и первый запуск с прогрессом.

### 2. Источники версий и файлов (качать всё в рантайме, jar-файлы НЕ распространять с приложением, это запрещает EULA)
- Vanilla: манифест Mojang `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json` → json версии → `downloads.server`.
- Paper/Folia: **только Fill API v3** `https://fill.papermc.io/v3/...` (v2 на api.papermc.io отключён). Ссылки на скачивание брать из ответа API, не собирать вручную. Обязателен заголовок User-Agent. В ответе есть минимальная версия Java и рекомендуемые флаги JVM, их использовать.
- Purpur: `https://api.purpurmc.org/v2/purpur`.
- Fabric: `https://meta.fabricmc.net/v2/versions/...` (готовый server launcher jar).
- NeoForge/Forge: скачать installer и запустить `--installServer` (у них свой run-скрипт и папка libraries, учесть при запуске).
- Bedrock Dedicated Server (BDS): официального API со списком версий нет. Формат ссылок `https://www.minecraft.net/bedrockdedicatedserver/bin-win/bedrock-server-<версия>.zip`. Актуальную версию определять парсингом страницы minecraft.net/download/server/bedrock (она иногда отдаёт Access Denied не-браузерным клиентам) с запасным вариантом: ручной импорт скачанного zip. Обрабатывать ошибки понятно для пользователя.
- Всем запросам ставить осмысленный User-Agent, кэшировать списки версий, проверять SHA1/SHA256, где API их даёт.

### 3. Java
- Приложение само скачивает нужный JRE (Eclipse Temurin через Adoptium API) в свою папку, системную Java не требует.
- Соответствие: MC 26.1+ → Java 25; 1.20.5-1.21.x → Java 21; 1.18-1.20.4 → Java 17; 1.17 → Java 16; 1.16.5 и старше → Java 8. Если API ядра (Paper Fill) сообщает минимальную Java, приоритет у него.
- Хранить несколько JRE параллельно, выбирать автоматически под сервер.

### 4. Управление сервером
- Старт / стоп / рестарт. **Остановка только через команду `stop` (для BDS тоже `stop`) с ожиданием сохранения мира.** Принудительное завершение только по отдельной кнопке с предупреждением и после таймаута.
- Процесс сервера привязать к Windows Job Object, чтобы при падении приложения сервер не оставался висеть. При закрытии окна: свернуть в трей или корректно остановить сервер (спросить, запомнить выбор).
- Консоль: живой лог с цветами и поиском, поле ввода команд (stdin), история команд.
- Статистика: RAM, CPU, TPS (Java: через вывод команд или Spark), онлайн игроков.
- Список игроков: кик, бан, оп, вайтлист в один клик.
- Редактор настроек без ручной правки server.properties: переключатели, ползунки, описания на русском.
- Автовыключение, если на сервере 0 игроков N минут (настраивается).
- Проверка занятости порта перед запуском, понятная ошибка.
- Несколько серверов, но одновременно по умолчанию запускается один (предупреждение, если второй займёт тот же порт).

### 5. Доступ для друзей
- Встроенный туннель **playit.gg**: приложение скачивает и запускает официальный агент playit, проводит привязку аккаунта (claim-ссылка), создаёт туннель нужного типа (Minecraft Java: TCP 25565; Bedrock: UDP 19132). Адрес показывать на карточке сервера с кнопкой «Копировать».
- Альтернатива: «Прямое подключение» (проброс порта вручную), показывать внешний IP и предупреждать про CGNAT/DS-Lite.
- Разрешение в брандмауэре Windows запрашивать с пояснением.
- Адреса на карточке сервера:
  - **Для друзей (playit)**: постоянный адрес туннеля. Туннель создаётся один раз при первом включении доступа, его id хранится в `server.json`. Агент playit на ПК один на все туннели, Hearth запускает его вместе с сервером. При удалении сервера предложить удалить и туннель.
  - **В одной сети (LAN)**: локальный IP ПК и порт, например `192.168.1.5:25565`.
  - **Для себя**: `localhost`.
  - **Прямое подключение**: внешний IP. Предупреждать, что у большинства провайдеров он меняется (после перезагрузки роутера и т.п.), и про CGNAT.

### 6. Режим для пиратских клиентов (только Java)
- Ставит `online-mode=false`.
- **Обязательно** предлагает и ставит плагин/мод авторизации: AuthMe Reloaded (Paper/Purpur), EasyAuth (Fabric). Без него показывать явное предупреждение: любой может зайти под чужим ником, включая ник администратора.
- Предупреждать, что при переключении online-mode у игроков меняются UUID и могут пропасть инвентари и права. Делать бэкап перед переключением.
- Для Bedrock такого режима нет (там вход через Xbox), пункт скрыть.

### 7. Моды и плагины
- Поиск и установка через **Modrinth API v2** (`https://api.modrinth.com/v2`, ключ не нужен, User-Agent обязателен). Фильтровать по версии игры и загрузчику (fabric, neoforge, forge, paper, purpur). Автоматически ставить обязательные зависимости (например, Fabric API).
- Показывать для каждого мода, где он нужен: «только сервер», «нужен и у игроков», «только клиент». Моды «только клиент» на сервер не ставить, объяснять почему.
- Обновление модов, отключение без удаления, проверка совместимости при смене версии сервера.
- CurseForge на этапе 1-2 не поддерживаем (нужен API-ключ по заявке, и многие авторы запрещают сторонние загрузки). Возможно позже.
- **Экспорт сборки для друзей**: .mrpack (импорт в Prism / Modrinth App) и zip с папкой mods для других лаунчеров, включая пиратские. Только моды, нужные клиенту.
- Bedrock: вместо модов аддоны (behavior/resource packs `.mcpack`/`.mcaddon`): импорт файлом и подключение к миру.

### 8. Оптимизация (пресеты)
- **Важно:** OptiFine работает только на клиенте и на сервере ничего не даёт, ставить его на сервер не нужно. В приложении это объяснить подсказкой, если пользователь ищет «OptiFine».
- Серверные пресеты (ставятся одной кнопкой с Modrinth):
  - Fabric: Lithium, FerriteCore, ModernFix, C2ME, Krypton, ServerCore, Alternate Current, Spark (проверять наличие под конкретную версию).
  - Paper/Purpur: само ядро уже оптимизировано, плюс Spark; оптимизированные настройки paper-global.yml / paper-world-defaults.yml (view-distance, simulation-distance, лимиты сущностей) пресетом «Производительность».
  - Флаги JVM: рекомендованные (из Paper API или Aikar's flags) по умолчанию.
- Клиентский пресет «Замена OptiFine» для друзей: Sodium, Iris, Lithium, FerriteCore, ImmediatelyFast, Entity Culling и т.п. Попадает в экспорт сборки для друзей (Fabric).
- Кнопка предгенерации мира (Chunky), чтобы не лагало при исследовании.

### 9. Бэкапы и миры
- Автобэкап по расписанию и перед каждым обновлением версии/ядра/модов. Хранить N последних (настраивается).
- Бэкап делать на работающем сервере корректно: `save-off` → `save-all flush` → копирование → `save-on` (для BDS: `save hold` / `save query` / `save resume`).
- Восстановление в один клик (с подтверждением, сервер должен быть остановлен).
- Импорт мира из одиночной игры (выбор из папки `.minecraft/saves` или zip), экспорт мира в zip.

### 10. Прочее
- Иконка в трее, запуск вместе с Windows (опционально).
- Уведомления Windows: сервер запущен, игрок зашёл, бэкап готов, ошибка.
- Обновление самого приложения (Tauri updater) на позднем этапе.
- Логи приложения в файл для отладки.

## Хранение данных
```
%APPDATA%/<AppName>/
  config.json            настройки приложения
  java/<версия>/         скачанные JRE
  cache/                 кэш манифестов и загрузок
  playit/                агент playit
  servers/<id>/
    server.json          метаданные: издание, ядро, версия, RAM, порт, опции
    server/              файлы сервера (jar, world, server.properties, mods, plugins)
    backups/             zip-бэкапы
```
Пользователь может сменить корневую папку серверов (игровой SSD и т.п.).

## Этапы
1. **MVP**: Java (Vanilla, Paper, Fabric), выбор версии, автоустановка Java, старт/стоп с корректным сохранением, консоль, редактор настроек, несколько серверов, сохранение между запусками.
2. playit-туннель, пиратский режим с авторизацией, бэкапы, импорт/экспорт мира, список игроков, статистика, трей, автовыключение.
3. Моды через Modrinth, пресеты оптимизации, экспорт сборки для друзей, Purpur, NeoForge/Forge.
4. Bedrock (BDS): создание, запуск, аддоны, бэкапы, playit UDP. Geyser для Java-серверов.
5. Полировка: уведомления, автообновление, английский язык.

## Подводные камни (держать в голове с самого начала)
- Сервер работает, только пока включён ПК пользователя.
- Сервер занимает RAM/CPU этого же ПК: при игре на нём же рекомендовать 4-6 ГБ серверу, предупреждать при нехватке.
- Версия Bedrock-клиента должна точно совпадать с версией BDS, а Bedrock обновляется часто: нужна простая кнопка «Обновить сервер» с бэкапом.
- Моды Fabric/Forge обычно нужны и у игроков, в отличие от плагинов Paper: интерфейс должен это ясно показывать.
- Внешние API меняются (пример: Paper отключил v2): весь код загрузчиков вынести в отдельные модули-«провайдеры» с понятными ошибками и тестами.
- Не хранить и не логировать токены playit в открытом виде, если этого можно избежать.

## Принятые решения (2026-11-22)
- Название: **Hearth**.
- Фронтенд: **React + TypeScript + Vite**, Tailwind CSS, компоненты shadcn/ui (Radix). Типы Rust → TS генерируются через **ts-rs** (`cargo test` кладёт их в `src/bindings`), обёртка команд в `src/lib/api.ts`. tauri-specta не взяли: на момент начала он всё ещё в RC.
- HTTP: reqwest с native-tls (SChannel Windows), без сборки C-зависимостей.
- Версия Java для Vanilla берётся из `javaVersion.majorVersion` в JSON версии Mojang. Порядок приоритетов: Paper Fill API, затем Mojang, затем таблица из раздела 3.
- Ручные команды пользователя идут в stdin. Служебные (`list`, TPS, `save-all` при бэкапе) идут через RCON на `127.0.0.1` со случайным паролем, наружу RCON не открывается.
- TPS: `tps` (Paper/Purpur), `/tick query` (Vanilla/Fabric 1.20.3+), иначе Spark.
- Хранение: `config.json` лежит в `%APPDATA%\Hearth`. JRE, кэш, playit и серверы лежат в `%LOCALAPPDATA%\Hearth`, корневую папку серверов можно сменить.
- Установщик NSIS ставит программу для текущего пользователя в тот же `%LOCALAPPDATA%\Hearth` (так делает шаблон Tauri). Удаление стирает только `hearth.exe`, `uninstall.exe` и ярлык, а `java`, `cache`, `logs`, `servers` остаются (проверено). Размер установщика около 3 МБ.
- Minecraft 26.x при первом запуске включает `white-list=true`; Hearth при создании сервера явно ставит `white-list=false`.
- Job Object в MVP. Процесс-сторож, который при падении приложения отправит `stop`, сделаем позже.
- Доступ для друзей включается сам при запуске сервера, кнопки «включить» нет (решение владельца, 2026-11-22): все пользователи включали бы его сразу. Единственное ручное действие — один вход в playit.gg, если напрямую не получилось и playit ещё не подключён. Адрес «В одной сети (Wi-Fi)» убран с карточки.
- Доступ для друзей (2026-11-22): сначала Hearth пробует прямое подключение без посредников. Через UPnP (crate `igd-next`) он находит роутер, проверяет, что у роутера свой белый IPv4 (не частный адрес, не CGNAT 100.64/10, не DS-Lite 192.0.0/24), и пробрасывает порт сервера на час с продлением каждые 20 минут, пока сервер работает. При остановке проброс снимается. Адрес показывается без порта, если порт 25565, и может меняться между запусками. Если напрямую нельзя, интерфейс объясняет почему и переходит к playit. IPv6 пока не используем: у многих игроков, особенно в России, его нет.
- playit при создании туннеля ключом агента: `/v1/tunnels/create` отвечает «failed to parse body» на любое тело, поэтому используется `/tunnels/create` (и `/tunnels/update` для смены порта). Новый агент сначала получает `AgentVersionTooOld`; Hearth запускает агент, ждёт, пока playit узнает его версию, и повторяет запрос.
- Токен playit хранится в Windows Credential Manager (запись `Hearth/playit.gg`). Crate `keyring` не взяли: в версии 4 он сменил API, а Credential Manager через уже подключённый crate `windows` занимает 60 строк.
- playit (2026-11-22, агент 2.0.x): Hearth скачивает с GitHub подписанный `playitd-windows-x86_64-signed.exe` последней стабильной версии 2.x (проверка SHA-256 из `digest` релиза) в `%LOCALAPPDATA%\Hearth\playit`. Подключение аккаунта, создание и удаление туннелей Hearth делает сам через API `api.playit.gg` (`/claim/setup`, `/claim/exchange`, `/v1/agents/rundata`, `/v1/tunnels/create`, `/v1/tunnels/config`, `/tunnels/delete`) с ключом агента типа `self-managed`. Агент запускается как `playitd --secret … --socket-path \\.\pipe\hearth-playit-<pid>` со своим каналом управления, поэтому не мешает отдельно установленному playit. Агент привязан к Job Object.
- При закрытии окна с запущенным сервером приложение по умолчанию сворачивается в трей.
- Макеты дизайна делаем перед созданием интерфейса, а не до каркаса.
- Адрес для друзей: у каждого сервера свой постоянный туннель playit, его id хранится в `server.json`. Адрес не меняется между запусками. Подробности в разделе 5.

2. Затем реализуй этап 1 и дай инструкцию, как собрать и запустить.
