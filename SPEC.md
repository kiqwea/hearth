# ТЗ: десктопное приложение для локальных серверов Minecraft («свой Aternos на ПК»)

## Суть
Приложение для Windows 10/11, которое в пару кликов создаёт и запускает сервер Minecraft **на компьютере пользователя**, чтобы играть с друзьями. Как Aternos, только локально, быстрее и удобнее. Сервер и мир сохраняются между запусками.

Целевой пользователь: геймер без опыта администрирования. Всё, что можно автоматизировать (Java, порты, EULA, конфиги), автоматизируем. Ручная правка файлов не нужна, но опытному пользователю доступна (кнопка «Открыть папку сервера»).

## Стек
- **Tauri v2**: бэкенд на Rust, фронтенд на TypeScript (фреймворк выберем вместе: Svelte или React).
- Сборка на Windows, установщик NSIS.
- Интерфейс: современный, тёмная тема по умолчанию, в духе Modrinth App / Prism Launcher. Детали дизайна обсудим отдельно.
- Язык интерфейса: русский, с заделом под i18n (английский позже).

## Функции

### 1. Создание сервера (мастер)
1. Выбор издания: **Java** или **Bedrock**.
2. Для Java: выбор ядра: Vanilla, Paper, Purpur, Fabric, NeoForge, Forge (Forge/NeoForge можно отложить на этап 3).
3. Выбор версии игры (по умолчанию последняя стабильная, переключатель «показывать снапшоты»).
4. Название, иконка, RAM (ползунок с рекомендацией по объёму ОЗУ ПК), режим игры, сложность, слоты, сид.
5. Опции: «Пиратские клиенты» (только Java), пресет оптимизации, Geyser (пускать Bedrock-игроков на Java-сервер).
6. Показать и принять EULA Mojang (обязательно, с ссылкой). Затем скачивание и первый запуск с прогрессом.

### 2. Источники версий и файлов (качать всё в рантайме, jar-файлы НЕ распространять с приложением, это запрещает EULA)
- Vanilla: манифест Mojang `https://piston-meta.mojang.com/mc/game/version_manifest_v2.json` → json версии → `downloads.server`.
- Paper/Folia: **только Fill API v3** `https://fill.papermc.io/v3/...` (v2 на api.papermc.io отключён). Ссылки на скачивание брать из ответа API, не собирать вручную. Обязателен заголовок User-Agent. В ответе есть минимальная версия Java и рекомендуемые флаги JVM, их использовать.
- Purpur: `https://api.purpurmc.org/v2/purpur`.
- Fabric: `https://meta.fabricmc.net/v2/versions/...` (готовый server launcher jar).
- NeoForge/Forge: скачать installer и запустить `--installServer` (у них свой run-скрипт и папка libraries, учесть при запуске).
- Bedrock Dedicated Server (BDS): официального API со списком версий нет. Формат ссылок `https://www.minecraft.net/bedrockdedicatedserver/bin-win/bedrock-server-<версия>.zip`. Актуальную версию определять парсингом страницы minecraft.net/download/server/bedrock (она иногда отдаёт Access Denied не-браузерным клиентам) с запасным вариантом: ручной импорт скачанного zip. Обрабатывать ошибки понятно для пользователя.
- Всем запросам ставить осмысленный User-Agent, кэшировать списки версий, проверять SHA1/SHA256, где API их даёт.

### 3. Java
- Приложение само скачивает нужный JRE (Eclipse Temurin через Adoptium API) в свою папку, системную Java не требует.
- Соответствие: MC 26.1+ → Java 25; 1.20.5-1.21.x → Java 21; 1.18-1.20.4 → Java 17; 1.17 → Java 16; 1.16.5 и старше → Java 8. Если API ядра (Paper Fill) сообщает минимальную Java, приоритет у него.
- Хранить несколько JRE параллельно, выбирать автоматически под сервер.

### 4. Управление сервером
- Старт / стоп / рестарт. **Остановка только через команду `stop` (для BDS тоже `stop`) с ожиданием сохранения мира.** Принудительное завершение только по отдельной кнопке с предупреждением и после таймаута.
- Процесс сервера привязать к Windows Job Object, чтобы при падении приложения сервер не оставался висеть. При закрытии окна: свернуть в трей или корректно остановить сервер (спросить, запомнить выбор).
- Консоль: живой лог с цветами и поиском, поле ввода команд (stdin), история команд.
- Статистика: RAM, CPU, TPS (Java: через вывод команд или Spark), онлайн игроков.
- Список игроков: кик, бан, оп, вайтлист в один клик.
- Редактор настроек без ручной правки server.properties: переключатели, ползунки, описания на русском.
- Автовыключение, если на сервере 0 игроков N минут (настраивается).
- Проверка занятости порта перед запуском, понятная ошибка.
- Несколько серверов, но одновременно по умолчанию запускается один (предупреждение, если второй займёт тот же порт).

### 5. Доступ для друзей
- Встроенный туннель **playit.gg**: приложение скачивает и запускает официальный агент playit, проводит привязку аккаунта (claim-ссылка), создаёт туннель нужного типа (Minecraft Java: TCP 25565; Bedrock: UDP 19132). Адрес показывать на карточке сервера с кнопкой «Копировать».
- Альтернатива: «Прямое подключение» (проброс порта вручную), показывать внешний IP и предупреждать про CGNAT/DS-Lite.
- Разрешение в брандмауэре Windows запрашивать с пояснением.
- Адреса на карточке сервера:
  - **Для друзей (playit)**: постоянный адрес туннеля. Туннель создаётся один раз при первом включении доступа, его id хранится в `server.json`. Агент playit на ПК один на все туннели, Hearth запускает его вместе с сервером. При удалении сервера предложить удалить и туннель.
  - **В одной сети (LAN)**: локальный IP ПК и порт, например `192.168.1.5:25565`.
  - **Для себя**: `localhost`.
  - **Прямое подключение**: внешний IP. Предупреждать, что у большинства провайдеров он меняется (после перезагрузки роутера и т.п.), и про CGNAT.

### 6. Режим для пиратских клиентов (только Java)
- Ставит `online-mode=false`.
- **Обязательно** предлагает и ставит плагин/мод авторизации: AuthMe Reloaded (Paper/Purpur), EasyAuth (Fabric). Без него показывать явное предупреждение: любой может зайти под чужим ником, включая ник администратора.
- Предупреждать, что при переключении online-mode у игроков меняются UUID и могут пропасть инвентари и права. Делать бэкап перед переключением.
- Для Bedrock такого режима нет (там вход через Xbox), пункт скрыть.

### 7. Моды и плагины
- Поиск и установка через **Modrinth API v2** (`https://api.modrinth.com/v2`, ключ не нужен, User-Agent обязателен). Фильтровать по версии игры и загрузчику (fabric, neoforge, forge, paper, purpur). Автоматически ставить обязательные зависимости (например, Fabric API).
- Показывать для каждого мода, где он нужен: «только сервер», «нужен и у игроков», «только клиент». Моды «только клиент» на сервер не ставить, объяснять почему.
- Обновление модов, отключение без удаления, проверка совместимости при смене версии сервера.
- CurseForge на этапе 1-2 не поддерживаем (нужен API-ключ по заявке, и многие авторы запрещают сторонние загрузки). Возможно позже.
- **Экспорт сборки для друзей**: .mrpack (импорт в Prism / Modrinth App) и zip с папкой mods для других лаунчеров, включая пиратские. Только моды, нужные клиенту.
- Bedrock: вместо модов аддоны (behavior/resource packs `.mcpack`/`.mcaddon`): импорт файлом и подключение к миру.

### 8. Оптимизация (пресеты)
- **Важно:** OptiFine работает только на клиенте и на сервере ничего не даёт, ставить его на сервер не нужно. В приложении это объяснить подсказкой, если пользователь ищет «OptiFine».
- Серверные пресеты (ставятся одной кнопкой с Modrinth):
  - Fabric: Lithium, FerriteCore, ModernFix, C2ME, Krypton, ServerCore, Alternate Current, Spark (проверять наличие под конкретную версию).
  - Paper/Purpur: само ядро уже оптимизировано, плюс Spark; оптимизированные настройки paper-global.yml / paper-world-defaults.yml (view-distance, simulation-distance, лимиты сущностей) пресетом «Производительность».
  - Флаги JVM: рекомендованные (из Paper API или Aikar's flags) по умолчанию.
- Клиентский пресет «Замена OptiFine» для друзей: Sodium, Iris, Lithium, FerriteCore, ImmediatelyFast, Entity Culling и т.п. Попадает в экспорт сборки для друзей (Fabric).
- Кнопка предгенерации мира (Chunky), чтобы не лагало при исследовании.

### 9. Бэкапы и миры
- Автобэкап по расписанию и перед каждым обновлением версии/ядра/модов. Хранить N последних (настраивается).
- Бэкап делать на работающем сервере корректно: `save-off` → `save-all flush` → копирование → `save-on` (для BDS: `save hold` / `save query` / `save resume`).
- Восстановление в один клик (с подтверждением, сервер должен быть остановлен).
- Импорт мира из одиночной игры (выбор из папки `.minecraft/saves` или zip), экспорт мира в zip.

### 10. Прочее
- Иконка в трее, запуск вместе с Windows (опционально).
- Уведомления Windows: сервер запущен, игрок зашёл, бэкап готов, ошибка.
- Обновление самого приложения (Tauri updater) на позднем этапе.
- Логи приложения в файл для отладки.

## Хранение данных
```
%APPDATA%/<AppName>/
  config.json            настройки приложения
  java/<версия>/         скачанные JRE
  cache/                 кэш манифестов и загрузок
  playit/                агент playit
  servers/<id>/
    server.json          метаданные: издание, ядро, версия, RAM, порт, опции
    server/              файлы сервера (jar, world, server.properties, mods, plugins)
    backups/             zip-бэкапы
```
Пользователь может сменить корневую папку серверов (игровой SSD и т.п.).

## Этапы
1. **MVP**: Java (Vanilla, Paper, Fabric), выбор версии, автоустановка Java, старт/стоп с корректным сохранением, консоль, редактор настроек, несколько серверов, сохранение между запусками.
2. playit-туннель, пиратский режим с авторизацией, бэкапы, импорт/экспорт мира, список игроков, статистика, трей, автовыключение.
3. Моды через Modrinth, пресеты оптимизации, экспорт сборки для друзей, Purpur, NeoForge/Forge.
4. Bedrock (BDS): создание, запуск, аддоны, бэкапы, playit UDP. Geyser для Java-серверов. **Отложен на будущее** (решение владельца, 2026-11-23): главное сейчас — Java; к Bedrock вернёмся, когда понадобится. Следом идут NeoForge/Forge (конец этапа 3) и этап 5.
5. Полировка: уведомления, автообновление, английский язык.

## Подводные камни (держать в голове с самого начала)
- Сервер работает, только пока включён ПК пользователя.
- Сервер занимает RAM/CPU этого же ПК: при игре на нём же рекомендовать 4-6 ГБ серверу, предупреждать при нехватке.
- Версия Bedrock-клиента должна точно совпадать с версией BDS, а Bedrock обновляется часто: нужна простая кнопка «Обновить сервер» с бэкапом.
- Моды Fabric/Forge обычно нужны и у игроков, в отличие от плагинов Paper: интерфейс должен это ясно показывать.
- Внешние API меняются (пример: Paper отключил v2): весь код загрузчиков вынести в отдельные модули-«провайдеры» с понятными ошибками и тестами.
- Не хранить и не логировать токены playit в открытом виде, если этого можно избежать.

## Принятые решения (2026-11-22)
- Название: **Hearth**.
- Фронтенд: **React + TypeScript + Vite**, Tailwind CSS, компоненты shadcn/ui (Radix). Типы Rust → TS генерируются через **ts-rs** (`cargo test` кладёт их в `src/bindings`), обёртка команд в `src/lib/api.ts`. tauri-specta не взяли: на момент начала он всё ещё в RC.
- HTTP: reqwest с native-tls (SChannel Windows), без сборки C-зависимостей.
- Версия Java для Vanilla берётся из `javaVersion.majorVersion` в JSON версии Mojang. Порядок приоритетов: Paper Fill API, затем Mojang, затем таблица из раздела 3.
- Ручные команды пользователя идут в stdin. Служебные (`list`, TPS, `save-all` при бэкапе) идут через RCON на `127.0.0.1` со случайным паролем, наружу RCON не открывается.
- TPS: `tps` (Paper/Purpur), `/tick query` (Vanilla/Fabric 1.20.3+), иначе Spark.
- Хранение: `config.json` лежит в `%APPDATA%\Hearth`. JRE, кэш, playit и серверы лежат в `%LOCALAPPDATA%\Hearth`, корневую папку серверов можно сменить.
- Установщик NSIS ставит программу для текущего пользователя в тот же `%LOCALAPPDATA%\Hearth` (так делает шаблон Tauri). Удаление стирает только `hearth.exe`, `uninstall.exe` и ярлык, а `java`, `cache`, `logs`, `servers` остаются (проверено). Размер установщика около 3 МБ.
- Minecraft 26.x при первом запуске включает `white-list=true`; Hearth при создании сервера явно ставит `white-list=false`.
- Job Object в MVP. Процесс-сторож сделан в 0.13.0 (см. ниже).
- Игроки и статистика (2026-11-23): при каждом запуске Hearth включает RCON со случайным портом и паролем (`enable-rcon`, `rcon.port`, `rcon.password`, `broadcast-rcon-to-ops=false`; в редакторе настроек эти ключи скрыты). Раз в 5 секунд (и сразу, когда в логе «joined/left the game») — память и процессор процесса (sysinfo), `list`, TPS (`tps` на Paper, `tick query` на Vanilla/Fabric; если команды нет, больше не спрашиваем). Действия вкладки «Игроки» — kick/ban/pardon/op/deop/whitelist add/remove через RCON, только на запущенном сервере; ник проверяется (`[A-Za-z0-9_]{1,16}`). На Paper команды с приставкой `minecraft:` (ванильные, не Bukkit), а Vanilla 26.x через RCON приставку не принимает («Unknown or incomplete command»), там без неё. Списки игроков — из usercache/ops/whitelist/banned-players.json. Проверено живыми тестами на Paper, Vanilla и Fabric 26.3.
- Бэкапы и миры (2026-11-23): zip в `servers/<id>/backups/`, имя `<дата_время>_<вид>.zip` (`auto`, `manual`, `before-restore`, `before-import`, `pirate`). На работающем сервере копия идёт через RCON: `save-off` → `save-all flush` (ждём до 2 минут) → zip → `save-on` даже при ошибке; на Paper с приставкой `minecraft:`. Автобэкап по умолчанию включён: раз в час, 10 последних, только если с прошлой копии на сервере кто-то был, первый — не раньше 10 минут после запуска; старые удаляются только автоматические, ручные и страховочные — нет. Восстановление и импорт — только на остановленном сервере: сначала страховочная копия текущего мира, мир распаковывается во временную папку `world-import.tmp` рядом и лишь потом заменяет `<level>`, `<level>_nether`, `<level>_the_end` (битый архив мир не портит). В zip главный мир — папка с level.dat ближе к корню и не `_nether`/`_the_end`; пути с `..` пропускаются. Миры одиночной игры ищутся в `.minecraft/saves` (и TLauncher), Prism/MultiMC, Modrinth App, CurseForge. Экспорт — один zip в формате одиночной игры: у старых версий Paper ад и энд лежат в отдельных папках (`world_nether/DIM-1`), при экспорте они кладутся внутрь мира; Minecraft и Paper 26.x и так хранят их внутри (`world/dimensions/minecraft/the_nether`). Файлы выбираются системным окном (`tauri-plugin-dialog`). Проверено живыми тестами.
- Purpur (2026-11-23): API `api.purpurmc.org/v2/purpur` (список версий от старых к новым, `latest` сборка, `md5` в ответе сборки; скачиваем по ссылке на конкретную сборку и проверяем MD5). Требований к Java в API нет: берём минимальную Java и флаги у Paper той же версии (Fill API), иначе таблица. Во всём остальном Purpur как Paper (`Loader::is_paper_like`): папка `plugins`, AuthMe, команды `minecraft:` и `tps`. Проверено живым тестом на 26.3.
- Плагины и моды (2026-11-23): вкладка «Плагины» (Paper/Purpur) или «Моды» (Fabric), у Vanilla её нет. Источник правды — папка `plugins`/`mods`: свой список Hearth не ведёт, jar опознаются по sha1 (`POST /v2/version_files`), названия и иконки — `GET /v2/projects`, обновления — `POST /v2/version_files/update` с загрузчиками и версией игры. Без Modrinth список показывается по именам файлов. Поиск: `/v2/search` с фасетами загрузчиков (Paper: paper/purpur/spigot/bukkit, project_type plugin; Fabric: fabric, mod), версии игры и `server_side` required/optional; пустой запрос — популярные. Установка берёт сборку сначала под «родной» загрузчик, затем совместимые, и ставит обязательные зависимости (до 4 уровней; уже стоящие не трогает). Новый мод можно поставить и на работающий сервер (заработает после перезапуска); обновлять и удалять — только на остановленном: Windows не даёт заменить jar, который держит Java. Плагин защиты ников удалить отсюда нельзя (он управляется в «Доступе»). У модов Fabric показывается `client_side`: «нужен игрокам», «по желанию», «только на сервере». Проверено живыми тестами (Purpur + LuckPerms, Fabric + Lithium, обновление старой версии).
- Пресет «Производительность» (2026-11-23): кнопка «Ускорить сервер» на вкладке модов/плагинов. Fabric: Lithium, FerriteCore, ModernFix, Krypton, Spark — только релизные версии под версию игры, иначе «пропущено» с причиной; C2ME не берём (под новые версии выходит альфой). Paper/Purpur: Spark уже встроен в Paper, поэтому только настройки — известные ключи `config/paper-world-defaults.yml` (optimize-explosions, max-entity-collisions 2, тик спаунеров 2 и травы 4, hopper ignore-occluding-blocks, prevent-moving-into-unloaded-chunks, лимиты arrow/experience_orb/snowball на чанк). YAML не парсится целиком: меняются только значения существующих ключей по точному пути и уровню отступа; файл появляется после первого запуска, до этого интерфейс просит запустить сервер. Всем: `simulation-distance` не больше 8 (прорисовка не меняется), не Paper — `sync-chunk-writes=false`. Повторное применение ничего не меняет.
- Предгенерация (2026-11-23): Chunky с Modrinth (`fALzjamp`, есть и для Fabric, и для Paper). Через RCON: `chunky spawn`, `chunky radius R`, `chunky start`; прогресс — `chunky progress` раз в 2 секунды (числа с запятой: `42,40%`); отмена — `chunky cancel` + `chunky confirm`. Если команды нет — понятная ошибка: поставить Chunky или перезапустить сервер. Проверено живыми тестами на Paper и Fabric 26.3.
- Обновление сервера (2026-11-23): блок «Версия сервера» в настройках. Проверка: новые стабильные версии игры — те, что в списке провайдера выше текущей (списки от новых к старым; снапшоты не предлагаем); новая сборка — `resolve` той же версии отдаёт другой `loader_version` (Paper/Purpur — номер сборки, Fabric — загрузчик). Откат на старую версию запрещён. План: для каждого мода из папки ищется файл под новую версию (готов / ещё не вышел / не с Modrinth). Обновление только на остановленном сервере: бэкап `before-update` → `game_version` в server.json и обычная установка ядра (при ошибке прежние метаданные возвращаются, старый jar на месте) → моды под новую версию. Моды Fabric без новой версии переносятся в `mods-disabled/` (иначе сервер не запустится), плагины Paper остаются. Если убран мод защиты ников — защита выключается с пояснением. Имя файла плагина защиты ников в server.json следует за его обновлением. Проверено живым тестом: Fabric 26.2 + Lithium → 26.3, запуск на новой версии; сборка Paper.
- Сборка для друзей (2026-11-23, только Fabric): моды сервера с `client_side` required, а с галочкой (по умолчанию включена) и optional — на Modrinth «нужен» ставят редко, даже голосовой чат помечен «по желанию». Серверные оптимизации из пресета (и C2ME) не берём, мод защиты ников тоже. Обязательные зависимости добавляются (версия с сервера, если есть, иначе релиз/бета под версию игры). «Замена OptiFine»: Sodium, Iris, Entity Culling, ImmediatelyFast, FerriteCore — релиз или бета (Sodium под новые версии выходит бетами), не альфа. Файлы не с Modrinth не попадают, интерфейс об этом говорит. `.mrpack` (formatVersion 1): только ссылки на cdn.modrinth.com с sha1 и sha512, `dependencies` minecraft + fabric-loader, `env` client required / server unsupported; если известен адрес (playit или прямой), в `overrides/servers.dat` (несжатый NBT) кладётся сервер — он сразу в списке серверов новой сборки. Zip: `mods/` с jar (с сервера или из кэша `cache/pack-mods` с проверкой sha1) и «КАК УСТАНОВИТЬ.txt»; servers.dat в zip не кладём, чтобы не затереть список серверов игрока. Проверено живым тестом (Voice Chat + Fabric API + замена OptiFine, оба формата).
- NeoForge и Forge (2026-11-23): версии NeoForge — `maven.neoforged.net/.../neoforge/maven-metadata.xml` (под 26.x номер `26.3.0.115` = игра 26.3, раньше `21.1.77` = 1.21.1; беты с дефисом), Forge — `promotions_slim.json` (рекомендованная сборка, иначе последняя; только 1.20.1+, старее ставится иначе). Скачивается установщик (sha1 из `.sha1` рядом в maven), Hearth запускает его как `java -jar установщик --installServer .` в папке сервера (Forge понимает только `--installServer`), в консоль идут только «installed successfully» и ошибки, установщик и его лог удаляются. В `server.json` `jar` = `libraries/.../win_args.txt`, запуск `java <флаги> @файл nogui`. Java — по таблице версий игры, флаги — Aikar. Моды как у Fabric (`mods`, загрузчик Modrinth `neoforge`/`forge`), пресет и сборка для друзей те же (в .mrpack `dependencies.neoforge`/`forge`), защиты ников нет. Проверено живыми тестами NeoForge 26.3 (+ Lithium, FerriteCore, Spark) и Forge 26.3 (+ Spark; Lithium/FerriteCore под Forge 26.3 нет).
- Уведомления и автозапуск (2026-11-23): уведомления шлёт само приложение (`app/notify.rs`) по событиям ядра — статус Running/Crashed, строка stdout `<ник> joined the game` (ник берётся после последнего `]: `, ровно одно слово, чтобы чат не притворялся входом), системные строки Hearth «Автобэкап…» и «На сервере никого нет…». Только если окно не в фокусе (свёрнуто или в трее) и `notifications` включены (по умолчанию да); дешёвая проверка события идёт до чтения server.json. Автозапуск — `tauri-plugin-autostart` с аргументом `--autostart`: окно в tauri.conf скрыто по умолчанию и показывается в setup, если аргумента нет; запись в автозагрузке сверяется с настройкой при каждом старте. У сервера флаг `start_with_app`: такие серверы запускаются по очереди при старте Hearth.
- Автовыключение (2026-11-23): в настройках сервера «Выключать, если никого нет» (по умолчанию «Никогда»; 10, 15, 30 мин, 1 или 2 ч). Отсчёт идёт по `list` через RCON, только когда сервер полностью запущен; выключение обычным `stop` с объяснением в консоли. Меняется на ходу, без перезапуска.
- Защита ников (AuthMe/EasyAuth) — отдельная настройка от пиратского режима (решение владельца, 2026-11-23): маленькой компании пароли при входе мешают. В мастере раздел «Кто сможет зайти»: пиратский режим и защита (по умолчанию включена); плагин ставится на этапе установки сервера, а если он не вышел под версию игры, сервер запускается без защиты с сообщением в консоли. В настройках сервера защиту можно включать и выключать отдельно; при выключении убирается только jar, пароли остаются в данных плагина.
- Пиратский режим (2026-11-22): переключатель в настройках сервера, только на остановленном сервере. Порядок: zip-бэкап мира (`servers/<id>/backups/`) → плагин авторизации с Modrinth (AuthMe Reloaded `authmereloaded` для Paper, сначала сборка под loader `paper`; EasyAuth `easyauth` + обязательный Fabric API для Fabric) → перенос файлов игроков (`<uuid>.dat/.dat_old/.json` по всей папке мира) и UUID в ops/whitelist/banned-players с лицензионных UUID из `usercache.json` на офлайн-UUID (`UUID.nameUUIDFromBytes("OfflinePlayer:"+ник)`) → `online-mode=false`, `enforce-secure-profile=false`. Выключение: бэкап, убрать jar плагина (данные с паролями остаются), обратный перенос по лицензионным UUID из Mojang API (`profile/lookup/bulk/byname`), `online-mode=true`. AuthMe переключается на русский (`messagesLanguage: ru`) один раз, после того как сам создаст config.yml. Для Vanilla авторизации нет: только с явным подтверждением и советом взять Paper. Проверено живыми тестами на Paper и Fabric 26.3.
- Доступ для друзей включается сам при запуске сервера, кнопки «включить» нет (решение владельца, 2026-11-22): все пользователи включали бы его сразу. Единственное ручное действие — один вход в playit.gg, если напрямую не получилось и playit ещё не подключён. Адрес «В одной сети (Wi-Fi)» убран с карточки.
- Доступ для друзей (2026-11-22): сначала Hearth пробует прямое подключение без посредников. Через UPnP (crate `igd-next`) он находит роутер, проверяет, что у роутера свой белый IPv4 (не частный адрес, не CGNAT 100.64/10, не DS-Lite 192.0.0/24), и пробрасывает порт сервера на час с продлением каждые 20 минут, пока сервер работает. При остановке проброс снимается. Адрес показывается без порта, если порт 25565, и может меняться между запусками. Если напрямую нельзя, интерфейс объясняет почему и переходит к playit. IPv6 пока не используем: у многих игроков, особенно в России, его нет.
- playit при создании туннеля ключом агента: `/v1/tunnels/create` отвечает «failed to parse body» на любое тело, поэтому используется `/tunnels/create` (и `/tunnels/update` для смены порта). Новый агент сначала получает `AgentVersionTooOld`; Hearth запускает агент, ждёт, пока playit узнает его версию, и повторяет запрос.
- Токен playit хранится в Windows Credential Manager (запись `Hearth/playit.gg`). Crate `keyring` не взяли: в версии 4 он сменил API, а Credential Manager через уже подключённый crate `windows` занимает 60 строк.
- playit (2026-11-22, агент 2.0.x): Hearth скачивает с GitHub подписанный `playitd-windows-x86_64-signed.exe` последней стабильной версии 2.x (проверка SHA-256 из `digest` релиза) в `%LOCALAPPDATA%\Hearth\playit`. Подключение аккаунта, создание и удаление туннелей Hearth делает сам через API `api.playit.gg` (`/claim/setup`, `/claim/exchange`, `/v1/agents/rundata`, `/v1/tunnels/create`, `/v1/tunnels/config`, `/tunnels/delete`) с ключом агента типа `self-managed`. Агент запускается как `playitd --secret … --socket-path \\.\pipe\hearth-playit-<pid>` со своим каналом управления, поэтому не мешает отдельно установленному playit. Агент привязан к Job Object.
- При закрытии окна с запущенным сервером приложение по умолчанию сворачивается в трей.
- Макеты дизайна делаем перед созданием интерфейса, а не до каркаса.
- Адрес для друзей: у каждого сервера свой постоянный туннель playit, его id хранится в `server.json`. Адрес не меняется между запусками. Подробности в разделе 5.
- Процесс-сторож (2026-11-24): Hearth при запуске стартует копию себя `Hearth.exe --watchdog <имя job>` (до Tauri и single-instance, без окна) и держит её stdin. После каждого запуска и остановки сервера туда уходит строка JSON со списком работающих серверов (id, PID, порт и пароль RCON). Job Object теперь именованный (`Local\Hearth-servers-<pid>-<n>`), сторож открывает его и держит: если Hearth упал, job не закрывается, сторож видит EOF на stdin с непустым списком и шлёт каждому серверу `stop` через RCON (ждёт RCON до 2 минут, сохранение до 2 минут), потом выходит, и Windows закрывает job, завершая остатки (агент playit). При обычном выходе список к этому моменту пуст. Если сторож пропал, Hearth запускает нового при следующем изменении списка. Лог сторожа — `logs/watchdog.*.log`. Проверено живым тестом: «Hearth» в отдельном процессе запускает Vanilla, его убивают, в latest.log сервера есть «Stopping server» и «Saving worlds»; без сторожа тот же тест падает.
- Скины Ely.by (2026-11-24): только в пиратском режиме (с лицензией скины и так настоящие). Paper/Purpur — плагин SkinsRestorer (`skinsrestorer`) с `api.elyByEnabled: true` в `plugins/SkinsRestorer/config.yml`; Fabric/NeoForge/Forge — мод SkinRestorer (`skinrestorer`, Suiranoil) с `join.autoFetch.providers: ["ely.by", "mojang"]` и `language: ru_ru` в `config/skinrestorer/config.json` (формат версии 3; файл старого формата без `version` не трогаем). Hearth кладёт настройки до первого запуска, плагин дописывает остальное сам; перед каждым запуском Hearth снова проверяет, что Ely.by включён. Ставится вместе с сервером из мастера (галочка «Скины Ely.by», по умолчанию включена) и при включении пиратского режима; выключение пиратского режима убирает jar. Отдельный переключатель в «Доступе»; в списке модов помечен и не удаляется оттуда; в сборку для друзей не попадает; имя файла в `server.json` (`skin_plugin`) следует за обновлением. Скины Ely.by подписаны ключом Mojang, их показывает обычный клиент. Проверено живыми тестами на Paper, Fabric, NeoForge и Forge 26.3.
- Отложено владельцем (2026-11-24): свой установщик на Rust вместо NSIS, Bedrock, английский язык (заготовка — ветка `wip/english-localization`). Не делаем: «как Hamachi» (игра в одиночном мире без сервера), UDP-порт голосового чата.
